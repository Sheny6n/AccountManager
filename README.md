# Account Manager

管理自己的 online footprint：记录网络身份、网站账户和留下的信息，发现不同 pseudonym（化名）之间可能暴露关联的线索，帮助维持自己希望保留的身份边界。

这个项目的核心问题是：**我在各个网站留下了什么？哪些线索可能把这些账户联系起来，最终指向现实中的我？**

## 项目定位

Account Manager 是一个本地桌面工具，用于梳理个人的网络身份与数字足迹。密码可以是账户记录中的一个字段，但产品重点是身份隔离、信息暴露和痕迹清理。

希望逐步帮助用户回答：

- 哪些账户属于同一个网络身份？哪些身份应该保持独立？
- 是否在本应隔离的身份之间复用了用户名、邮箱、手机号、头像或个人简介？
- 哪些资料对公众可见，哪些仅平台知道，哪些信息的可见性尚不明确？
- 账户之间是否存在主动公开的链接、单点登录或恢复方式等关联？
- 哪些账户已经不用了，需要修改资料、解除关联或申请删除？

例如：论坛账户和作品展示账户分别使用两个化名，却复用了相同头像。工具应帮助用户看见这条关联，再由用户判断它是否符合自己的身份隔离意图。同一个身份内有意复用资料，不应自动被当作问题。

## 设计原则

1. **以用户的隔离意图为准。** 允许用户明确哪些身份可以关联、哪些需要隔离。
2. **区分不同观察者。** 公开资料带来的关联，与平台通过注册或恢复信息建立的关联，应分别呈现。
3. **让判断有据可查。** 关联提示应说明涉及哪些账户、哪个字段、依据是什么，以及信息是否经过确认。
4. **保留不确定性。** 没有发现已记录的关联，不代表不存在其他关联；不使用缺乏依据的“匿名安全分”。
5. **保留用户控制权。** 本地记录的修改与远程网站操作应明确区分；远程操作需要用户明确授权。

## 已有功能

- **本地资料库**：创建、打开 `.am` 文件，支持多个标签页。
- **可选加密**：设置主密码时使用 Argon2id 派生密钥、SQLCipher 加密数据库；留空则创建未加密资料库。
- **账户整理**：分组、分组重命名、账户编辑、复制和置顶。
- **自定义字段**：记录用户名、邮箱、手机号、地区、备注等信息，支持配置快捷添加字段。
- **全局搜索**：搜索当前资料库内所有分组，匹配网站名称、字段名和字段值；结果显示所属分组，可点击跳转。取消 `All groups` 后搜索当前分组。
- **回收站**：账户和分组删除后可恢复；恢复分组会带回其中的账户，之前单独删除的账户仍保留在回收站。
- **使用设置**：自动锁定、可配置快捷键、表格列宽和加密资料库主密码修改。

当前的分组只是整理方式，自定义字段也尚未具有身份关联分析语义。下文中的身份档案、可见性标记和关联检查均为规划功能。

### 回收站与网站销户的区别

`Trash` 只把本地记录移入回收站，**不会删除对应网站的账户或清除网站上的资料**。回收站在关闭应用后仍然保留；其中的分组名称仍被占用，可恢复后重命名。

## 接下来做什么

### 1. 身份档案与账户归属

建立独立的“身份档案”（Persona），例如现实身份、公开创作身份、社区化名。每个网站账户可以关联身份档案，也可以暂时保持未分类。

- 记录身份的用途、说明，以及与其他身份的隔离要求。
- 支持同一网站存在多个账户，并为它们指定不同身份。
- 保留分组作为独立的整理维度，避免把现有分组自动解释为身份。
- 区分资料库（Profile 文件）与身份档案（Persona）：一个资料库中可以包含多个身份。

这是后续检查的基础：只有知道用户希望隔离什么，才能判断跨账户复用是否值得提醒。

### 2. 结构化线索与可见性

在保留自由字段的基础上，为常见线索提供明确类型：用户名、公开邮箱、注册邮箱、恢复邮箱、手机号、头像引用、个人简介、个人链接和登录提供方。

- 为每条线索记录可见性：公开、受限可见、仅平台可见或未知。
- 区分注册用途、公开展示用途和账户恢复用途。
- 可记录资料页面地址、核查日期与备注，方便后续复查。
- 已有字段保留原值；类型转换由用户确认，不根据字段名称默默推断。

### 3. 可解释的跨身份关联检查

第一版先检查已记录的用户名、邮箱、手机号和链接是否在需要隔离的身份之间重复出现。

- 每条提示显示涉及的身份、账户、重复字段和可见性。
- 区分公开可见的关联与平台内部信息的关联。
- 允许标记为有意共享、待核查或已处理。
- 保留原值，采用明确的比较规则；避免激进归一化把不同值误判为相同。

头像相似性、简介相似性和更复杂的推断可以后续加入。第一版优先让每条提示容易核实。

### 4. 痕迹清理工作流

为网站账户记录生命周期：使用中、停用、待清理、已申请删除、已确认删除。

- 为修改用户名、替换头像、解除公开链接、申请销户等行动建立待办。
- 保存删除入口、申请日期、确认日期及核查备注。
- 区分用户标记已完成与实际核查结果。
- 远程账户删除后，可以保留最少的本地处理记录，避免再次注册或重复排查。

### 5. 身份关系视图

在结构化数据和关联规则稳定后，展示身份、账户及共享线索之间的关系。点击连接即可查看依据，并按可见性或待处理状态筛选。

**建议实施顺序：身份档案 → 结构化线索 → 关联检查 → 清理工作流 → 关系视图。**

## 能力边界

目前的信息由用户手动录入，工具不会自动扫描网站、检查账户是否真的已删除，或发现未录入的资料。

未来的关联检查也只能基于可获取的数据提供线索，不能保证化名无法被追溯。IP、浏览器指纹、活动时间、内容特征以及平台掌握的其他信息，不在当前检查范围内。

资料库可能集中保存多个身份之间的映射。文件是否加密取决于创建时是否设置主密码；它与网站上的资料可见性是两个独立问题。

## 本地开发

技术栈：Rust、Iced、SQLite / SQLCipher、Argon2id。

安装 Rust 工具链和本机构建工具后，在项目目录运行：

```sh
cargo run
```

构建与验证：

```sh
cargo build
cargo test
cargo fmt --check
```

首次构建需要获取依赖，并编译随依赖提供的 SQLCipher / OpenSSL；本机构建工具要求取决于操作系统。

代码结构：

| 文件 | 职责 |
| --- | --- |
| `src/main.rs` | 桌面界面、交互与应用状态 |
| `src/model.rs` | 分组、账户及字段数据模型 |
| `src/db.rs` | 数据存储、结构升级、回收站与恢复 |
| `src/crypto.rs` | 密钥派生与加密辅助函数 |
